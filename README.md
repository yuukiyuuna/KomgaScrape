# Komga Metadata Scraper

一个用于 [Komga](https://komga.org/) 的用户脚本（Userscript），可以从外部数据源抓取漫画 / 书籍的元数据，并写回 Komga。

当前版本：**v1.2.17**

## 功能概览

- 在 **系列详情页 / 书籍详情页** 自动注入“刮削”按钮。
- 支持手动从以下数据源抓取元数据：
  - [Bangumi / 番组计划](https://bgm.tv/) —— 官方 `api.bgm.tv` 接口（推荐）。
  - **同人本搜索（v1.2.13 起，四源串行链）** —— 依次检索 [FANZAブックス](https://book.dmm.co.jp/)（DMM 电子书区）→ [DLsite](https://www.dlsite.com/books/)（成年漫画 / 単話）→ [FANZA 同人](https://www.dmm.co.jp/dc/doujin/)（同人区）→ [駿河屋](https://www.suruga-ya.jp/)（兜底）。某源出现与书名匹配的结果即在该源停下展示；有结果但不匹配、或该源请求失败时，自动继续搜索下一个源；**结果绝不混排**，每条搜索结果的卡片上都标明了来源（`FANZAブックス` / `DLsite` / `FANZA同人` / `駿河屋`）。DLsite 的成年漫画（如 `BJ` 系）在 DMM 一般归电子书区而不是同人区，所以 FANZAブックス 排在链路第一站；**DLsite 详情自 v1.2.13 起改走站点自用的 JSON 接口（`api/=/product.json`），搜索仍解析搜索页 HTML —— 两者都只做直连，直连不通时请把 `www.dlsite.com` 交给浏览器/系统代理**（脚本不内置代理）；駿河屋 直连被拦时自动改用「桥接标签页」重取（见 [2.4 駿河屋 / DLsite 直连被拦时](#24-駿河屋--dlsite-直连被拦时v1211-起)）。进入结果弹窗后，顶部还可手动切换四源：点某一源即单独检索该源（仅显示所选源结果，不与其他源混排）。
- 在 **系列详情页** 额外提供“自动刮削”按钮：按 **书籍文件名解析出的卷号**（`第10巻` / `Vol.3` / `#07` / `上` / `下` 等，含 `前編` / `後編` / `上巻` 这类非数字分卷）与 Bangumi 系列下的分卷条目 (`/v0/subjects/{id}/subjects`) 匹配，批量写入并在 Komga 中加锁（标题、简介、发售日期、ISBN、作者、来源链接、序号等）。未匹配的书可在确认弹窗里**手动指定**对应的 Bangumi 条目，也可用「按顺序配对」批量兜底（见 [2.5 非数字分卷与手动指定](#25-非数字分卷与手动指定v1212-起)）。
- 搜索结果弹窗可按 **系列 / 单行本** 过滤、可调整拉取与显示条数、可「加载更多」，长标题鼠标悬停显示完整书名（见 [2.3 搜索结果弹窗](#23-搜索结果弹窗v128-起)）。
- **书籍页同人本刮削同步系列**：在书籍详情页用「同人本搜索」刮削时，会把作品信息**同步写入所属系列**（系列标题 / 排序标题 / 简介 / 出版社 / 别名 / 阅读方向 / 语言 / 分级，见「书籍页同步系列字段」说明）；**系列文件夹名识别为日文时，系列阅读方向自动预选「从右到左」**。
- **状态下拉**：系列页预览弹窗的「状态」改为固定值下拉（连载中 / 已完结 / 弃坑 / 休载），无需手动输入；系列页选择「同人本搜索」时卡片会以浅红气泡提示「同人本推荐在书籍中刮削而非本页面刮削」（与 Bangumi 卡片的「推荐」徽标同款气泡样式、仅换配色）；书籍页不再显示「新」徽标。
- 可选快捷键：`Ctrl+Shift+S` 打开刮削菜单；`Ctrl+Shift+,` 打开设置面板。

> **自动刮削仅支持 Bangumi 源。** 同人本搜索链路主要面向同人本 / 単話，命名不规范且数量通常较少，因此不提供自动刮削；如需要请使用页面上的“刮削”按钮手动执行。

## 安装

1. 在浏览器中安装一个 Userscript 管理器，例如：
   - [Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox）。
   - [Violentmonkey](https://violentmonkey.github.io/)（开源推荐）。
2. 把本仓库中的 [`komga-metadata-scraper.user.js`](./komga-metadata-scraper.user.js) 内容复制到管理器新建的脚本中，或通过 “从 URL 安装” 加载。
3. **重要：** 打开脚本、把顶部 `// @match {你自己的komga网站地址}` 替换为你自己的 Komga 地址（例如 `https://komga.example.com/*` 或 `http://192.168.0.10:25600/*`）。

4. 保存脚本，刷新 Komga 页面即可看到 “刮削” / “自动刮削” 按钮。

> **Tampermonkey 用户请注意：** 脚本中的 `駿河屋` 兜底源需要 `GM_cookie`（复用浏览器里已通过的 Cloudflare 校验 Cookie）以及 `GM_openInTab` / `GM_addValueChangeListener`（被 Cloudflare 拦下时改用「桥接标签页」重取）权限，`@match` 里带有 `https://www.suruga-ya.jp/*`。更新脚本后管理器会提示权限变化，请点击允许；否则 `駿河屋` 直连被拦时无法自动改用桥接标签页。（v1.2.13 起已移除 `https://www.dlsite.com/*` 的 `@match`：DLsite 不再使用桥接标签页。）

> 如果访问 `api.bgm.tv` 有困难，可在浏览器级别配置代理把 `api.bgm.tv` / `bgm.tv` 的请求走代理（脚本本身不再做代理处理）。

## 使用方式

### 1. 手动刮削

1. 打开一个**系列**或**书籍**详情页，点击右上角 “刮削”。
2. 在弹出菜单中选择数据源（Bangumi 或「同人本搜索」）。
3. 确认搜索结果，脚本会自动填充标题、简介、出版日期、ISBN、作者、标签等字段。
4. 点击“写入”后，字段会被写回 Komga，并自动在 Komga 侧锁定（`*Lock=true`），防止被 Komga 内置的元数据扫描覆盖。

> 书籍页的搜索关键词与预览里的「序号 / 排序序号」默认值同样取自**文件名解析出的卷号**（解析不到才用 Komga 当前值），避免 Komga 按位置重编号后搜错卷。

### 2. 自动刮削（仅 Bangumi，仅限系列页）

**前置条件：** 该系列必须先被手动刮削过（或手动在 metadata.links 中添加 `https://bgm.tv/subject/{id}` 的链接），这样脚本才能知道它在 Bangumi 上的 subject id。

**步骤：**
1. 进入系列详情页，点击 "自动刮削" 按钮。
2. 脚本先读取该系列下的全部书籍，再从 `GET https://api.bgm.tv/v0/subjects/{seriesSubjectId}/subjects` 读取系列中的分卷 / 章节条目；只取其中 `type=1`（书籍）的条目，并让 `relation=单行本` 的条目优先参与卷号匹配（避免广播剧、动画、相同世界观等条目抢占卷号）。
3. 弹出**确认对话框**：显示系列名、书籍总数、自动匹配数、手动指定数、跳过数、重复卷号行数，并**逐本列出「卷号 / 文件名 → 匹配到的 Bangumi 条目」**（未匹配的书标出原因并给出「手动指定」入口；卷号重复会带 ⚠ 并注明与哪一本重复；卷号靠 Komga 位置序号兜底的行会标「位置推断」）。可逐本勾选 / 取消，也可用「按顺序配对…」批量兜底（先预览再应用）。点击 "开始" 进入批处理。
4. 逐本进行：按**书籍文件名解析出的卷号**（解析不到时退回 Komga 已有的 `metadata.number`）与 Bangumi 条目中解析出的卷号匹配；匹配成功后调用 `GET https://api.bgm.tv/v0/subjects/{id}` 拉取详细元数据，**直接写入并加锁**（不再要求手动确认）。
5. 每本书的详情拉取失败会自动**最多重试 2 次**（间隔 1.5 秒）。
6. 最后弹出**汇总对话框**：成功写入 / 跳过（未匹配） / 失败 / 总计。

**匹配规则（v1.2.9 起）：**

- **卷号来源：** 以 **Komga 书籍文件名**为准。Komga 扫描系列时会把书按文件名排序后**按位置重编号**（`SeriesLifecycle.sortBooks` 把 `BookDto.number` 与 `metadata.number` 都设成 1..N 的位置序号），所以「第1/2/5/7/10巻」在库里可能显示为 1..5；脚本不再使用这个位置序号，而是从文件名解析卷号。
- **文件名解析：** 依次尝试显式卷标 `第N巻` / `第N卷` / `N巻` / `第N話`（`話` / `回`）/ `Vol.N` / `Volume N` / `#N` / `N冊`，支持 `10.5` 这类小数，全角数字自动转半角；都匹配不到时取文件名中**最后一个** 1–3 位独立数字（如 `Series 10`；四位年份不会被误判）。仍然解析不到时，退回使用 Komga 已有的 `metadata.number`。
- **非数字分卷（v1.2.12 起）：** 除数字卷号外还认 `上` / `中` / `下` 这类分卷标记（写法包含 `前編` / `前篇` / `上巻` / `上卷`、`中編` / `中篇` / `中巻` / `中卷`、`後編` / `後篇` / `下巻` / `下卷`），以及 `一巻` / `三冊` 这类汉字数字卷标（换算成 1–10）。标记必须是**独立片段**（`作品名 上` / `作品名(上)`）或**带 巻 / 編 / 篇 后缀**（`作品名上巻` / `作品名前編`）；`上野さんは不器用`、`下北沢`、`坂道の上` 不会被误判。数字与标记同时存在时拼成组合键（`第3巻 上` → `3上`），这样「1上」「1下」不会撞成同一卷。
- **Bangumi 侧：** 同样优先匹配标题中的显式卷标，未找到时取标题里首个 1–3 位独立数字（排除年份这类误匹配）；同一卷号有多条条目时取第一条。
- **比较方式：** 卷号按**数值等价**比较（`10`、`10.0`、`"10"` 视为同一卷）。
- **序号写回：** 只要卷号是从文件名解析出来的，脚本会把它写回 `number`（字符串）与 `numberSort`（数字）并加锁，从而**修正**库里被按位置重编号的序号（如 1..5 → 1,2,5,7,10）。非数字分卷把标记写进 `number`（`上` / `下` / `3上`），`numberSort` 取排序值（`上` / `中` / `下` → `1` / `2` / `3`，`3上` → `3`；所以上下两卷时「下」的排序值是 3，相对顺序仍正确）；靠 `metadata.number` 兜底匹配的书不写回序号。
- **跳过：** 未解析出卷号（多为特典 / 画集）、或 Bangumi 侧没有对应卷号（缺卷或命名不符）的书会报告为"跳过"，不会写入；确认弹窗里可以逐本「手动指定」或按顺序批量配对来兜底。

**字段加锁策略：** 自动刮削写入的所有字段（title、summary、releaseDate、isbn、authors、links、number、numberSort 等）会被自动附加 `*Lock=true`，避免被 Komga 内置扫描覆盖。

### 2.1 Bangumi 接口降级（v1.2.6 起）

Bangumi 的 v0 接口（`api.bgm.tv/v0/...`）偶尔会整段不可用（例如未缓存请求一律返回 `502`，只有 Cloudflare 缓存里的旧数据还能读到）。脚本按下面的顺序自动降级，尽量不影响刮削：

- **搜索：** `POST /v0/search/subjects` → 失败或无结果时改用旧版接口 `GET /search/subject/{keyword}?type=1&responseGroup=small&max_results=25`（文档上限 25）。搜索参数严格按官方文档构造：`sort=match`、`filter.type=[1]`，且**不传** `filter.nsfw`（文档中 `true` 表示“只返回 R18”，传了会把普通条目全部过滤掉，这是“明明有却搜不到”的常见原因）。
- **详情：** `GET /v0/subjects/{id}` → 失败时解析网页 `https://bgm.tv/subject/{id}` 的 infobox（ISBN / 发售日期 / 页数 / 作者 / 别名等字段与 v0 一致）→ 再失败时退回旧版 JSON `GET /subject/{id}?responseGroup=large`。
- **系列子条目：** `GET /v0/subjects/{id}/subjects` → 失败时解析网页 `https://bgm.tv/subject/{id}/offprints` 的单行本列表。
- v0 连续失败后会在 **5 分钟**内跳过 v0 直接走降级（避免自动刮削时每本书都白等一次超时）；v0 恢复后自动重新优先使用。
- 如果两条链路都失败，脚本会明确提示"Bangumi 搜索接口不可用 / Bangumi 接口不可用"（并带 HTTP 状态），不再误报成"未找到匹配结果"。

### 2.2 系列出版社与语言自动识别（v1.2.7 起）

**出版社（`publisher`）** —— 系列详情页手动刮削时，预览弹窗会新增「出版社」字段：

- Bangumi 源：取 infobox 中「出版社 / 出版者 / 出版商」条目（排除「连载杂志」等干扰项）。
- FANZA 同人 / FANZAブックス 源：取详情页信息表中的 出版社 / ブランド / メーカー / レーベル / サークル 首个值（FANZAブックス 详情页的出版社在信息表 `出版社` 行；FANZA 同人 没有社名时回退取圈名）。DLsite 源取详情 JSON 的 `maker_name`（出版社 / サークル；取不到时回退 `label_name`）。
- 取得值时才显示该字段；取消勾选则不写入，写入时按现有策略加锁（`publisherLock=true`）。

**语言（`language`）** —— 同一个预览弹窗会出现「语言 (按文件夹名识别)」字段，其值由该系列在磁盘上的**文件夹名**字符属性推断：

| 文件夹名包含 | 写入的 language |
| --- | --- |
| 假名（平假名 / 片假名 / 半角片假名） | `ja` |
| 谚文（韩文） | `ko` |
| 汉字（且无假名、无谚文） | `zh` |
| 英文字母（整名只含英文字母 / 拉丁字母，且无假名、谚文、汉字） | `en` |
| 其它（纯数字 / 符号，或含西里尔 / 希腊 / 阿拉伯等其它文字） | 不写入，预览中不显示该字段 |

- 判定直接基于**完整文件夹名**，不做括号剔除：只要出现假名就判为 `ja`，因为日文名常把 `全巻セット`、`DL版` 这类标签写在方括号里（所以 `[全巻セット] ONE PIECE` 判为 `ja`，而不是 `en`）。
- 优先级为 **假名 > 谚文 > 汉字 > 英文**：`ONE PIECE 第1巻` 含汉字且无假名，判为 `zh`；只有整名不含以上文字、且（除空格 / 数字 / 符号外）全部由英文字母构成时才判为 `en`，例如 `ONE PIECE`、`Fate/stay night`。
- **仅在 Komga 中该系列的 language 为空时才填充**：已有值（或已锁定 `languageLock=true`）时预览不显示该字段，避免二次刮削改变既有语言设置。
- 识别结果**不参与标题选择**：标题仍按 Komga 现有的 language 元数据决定（`zh` 用中文名，其它用日文原名）。
- 已知限制：纯汉字的日文名（如 `東京喰種`）无法与中文名区分，会判为 `zh`；此时可在预览弹窗中手动改成 `ja`。
- **语言识别为日文时阅读方向自动改为「从右到左」**：系列页预览弹窗的「阅读方向」下拉会预选「从右到左」（覆盖系列当前值），书籍页同人本刮削的「系列阅读方向（同步到系列）」同规则；用户仍可在弹窗里改选或取消勾选。

> `publisher` 与 `language` 都是 Komga 的**系列级**字段：Komga 的书籍元数据 API 不支持这两个字段。系列页刮削直接写系列；书籍页用「同人本搜索」刮削时会随「同步到系列」一起写入所属系列（见下文「书籍页同步系列字段」），Bangumi 源与自动刮削不涉及。

### 2.3 搜索结果弹窗（v1.2.8 起）

搜索完成后弹出的结果列表支持类型过滤、数量控制与长标题悬浮提示。

**结果类型过滤（仅 Bangumi）**——Bangumi v0 搜索响应自带 `series` 字段（「是否为书籍系列的主条目」），脚本据此把结果分为**系列**与**单行本**两类，并在卡片信息行显示对应徽标（绿色「系列」/ 灰色「单行本」）：

- **系列详情页刮削默认「仅系列」，书籍详情页刮削默认「仅单行本」**，可在下拉中随时切回「全部」或另一类。
- 旧版降级接口与「同人本搜索」链路（FANZAブックス / DLsite / FANZA同人 / 駿河屋）不返回该字段：此时不显示类型下拉，也不隐藏任何结果——**类型未知的结果在任何档位下都会展示**，宁可多显示也不误藏。
- 过滤后一条不剩时，列表区提示「当前过滤条件下没有结果」并给出 **「显示全部 N 条结果」** 按钮一键恢复，不会被误报成「未找到匹配结果」。

**同人本四源切换（v1.2.13 起）**——「同人本搜索」首次仍按默认链路（FANZAブックス → DLsite → FANZA同人 → 駿河屋，命中即停）检索；进入结果弹窗后顶部显示四枚源按钮，当前命中源高亮：

- 点击某一源即用相同关键词**只检索该源**，结果整体替换列表（仅显示所选源结果，不与其他源混排）；同一次弹窗内已取过的源结果会缓存复用，避免重复请求。
- 该源返回 0 条时保留切换栏并显示空态「「XXX」未返回结果（未与其他源混排）」；请求失败时保留切换前列表，仅提示「「XXX」搜索失败：原因」，按钮随即恢复可点。
- 四源链路落空（全 0 条，或部分/全部源请求失败）不再弹错误框：直接进入可编辑关键字的手动模式——编辑搜索词本身不触发任何搜索，点哪个源按钮就用当前搜索词做该源的单独搜索，可随时切换；另有「🔁 按当前搜索词重跑四源链」按钮（点击才跑）。

**结果数量与「加载更多」**：

| 设置项（设置面板 → 🔎 搜索结果） | 配置键 | 默认 | 说明 |
| --- | --- | --- | --- |
| 单次拉取条数 | `searchFetchLimit` | 50 | 范围 10–100；旧版降级接口按文档上限收紧到 25 |
| 默认显示条数 | `searchVisibleCount` | 10 | `0` 表示显示全部 |
| 单个搜索源超时 | `searchSourceTimeoutSec` | 10 | 单源（含 Bangumi 与 駿河屋 直连搜索/详情）最长等待秒数（3–30），超时自动跳到下一源；駿河屋 被 Cloudflare 拦下后转「桥接标签页」，桥接固定等 40 秒（不受此设置影响）；其余源点选结果后的详情抓取固定 15 秒限时 |

- 单源 0 命中且关键词含圆形字符（◯ / ○ / 〇 / ◎ …）时，DLsite / FANZAブックス / FANZA同人 会自动换成 `〇` / `◯` / `○` 写法重试（命中即停）；请求失败不重试，駿河屋 模糊匹配不做变体。
- 駿河屋 直连被 Cloudflare 拦下后转「桥接标签页」，桥接是独立于单源超时的一段预算（v1.2.16 起）：直连阶段按设置的秒数限时，桥接固定等 40 秒 + 5 秒宽限（含用户完成人机验证的时间）；弹窗内手动搜索、四源链路内尝试与**选中结果后的详情补全**（v1.2.15 起）同口径。详情补全失败静默退回列表页数据，不弹错；桥接 40 秒内未完成验证时提示「人机验证未在 40 秒内完成」并进入 5 分钟直连冷却。
- 弹窗内「显示数量」下拉可临时切换 **10 / 25 / 50 / 全部**（选项随配置值动态补充），卡片列表超过一屏时在弹窗内滚动，不撑高整个弹窗。
- Bangumi v0 命中数超过已加载条数时，底部出现 **「加载更多（还有 N 条）」**，按 `offset` 继续拉取并累加；点击后「显示数量」自动切到「全部」，避免刚拉到的结果不可见。
- 计数行形如「共 120 条结果，已加载 50 条，当前显示 10 条（过滤：仅系列，符合 17 条）」；旧版降级接口没有命中总数，只显示「已加载 N 条结果」。
- 旧版降级接口与「同人本搜索」链路（FANZAブックス / DLsite / FANZA同人 / 駿河屋）都不提供「加载更多」；这些源直接解析各自搜索列表页（详情等选中后再抓；FANZA 同人区每页固定 120 条），都不参与类型过滤。

**长标题悬浮提示**——书名与原名两行仍按单行省略号截断，鼠标移入时用悬浮层显示完整文字：只有真的被截断（`scrollWidth > clientWidth`）时才提示，列表滚动、鼠标移开或弹窗关闭时立即收起。

### 2.4 駿河屋 / DLsite 直连被拦时（v1.2.11 起）

駿河屋 全站挂在 Cloudflare 后面。如果本机出口 IP 被它判为可疑，**每个请求**都会拿到 `403` + `Just a moment...` 的人机校验页；这类「托管挑战」只有真实浏览器导航才过得去，而 `GM_xmlhttpRequest` 不是浏览器导航（发起方是扩展上下文、缺少 `sec-fetch` 导航类请求头、TLS/HTTP2 指纹也不同），所以**即使你已经在新标签页里手动通过了校验，脚本请求依旧会被当成没过校验**。

脚本对駿河屋的处理：直连被拦下时，自动在后台**新开一个真实标签页**访问同一个目标页 URL（**v1.2.15 起同一条桥接既服务搜索列表页、也服务「选中结果后补抓的商品详情页」**），由该标签页（同一份脚本，`@match` 含 `https://www.suruga-ya.jp/*`）在页面就绪后把 HTML 回传，Komga 页照常解析、写回。

- 标签页停在人机校验页时，页面会提示「请切到 駿河屋 标签页完成验证」——切过去点一下「确认」即可（请在 40 秒内完成验证），脚本会自动继续。
- 取到结果后桥接标签页会自动关闭；40 秒内没取到结果时：搜索会以「人机验证未在 40 秒内完成」报错（并进入 5 分钟直连冷却），「选中结果后的详情补全」则只 `console.warn` 并**静默退回列表页数据**（不弹错、不阻断刮削）。
- 设置面板可关闭该行为（「駿河屋 被拦截或无法直连时自动开「桥接标签页」重取」，默认开启）；关闭后只做直连请求。
- 若直连与桥接都失败：駿河屋 基本可以确定是出口 IP 被判定为可疑，**只**把 `suruga-ya.jp` 交给代理（换出口 IP）后重试即可。代理不需要写进脚本（换 IP 后校验会重新触发一次，属正常现象）。

**DLsite（v1.2.13 起）不再使用「桥接标签页」**：搜索解析搜索页 HTML、详情调用站点自用的 JSON 接口 `api/=/product.json`，两者都只做直连 —— 直连不通（超时 / 年龄确认页 / 被拦）时直接报错，不再自动开标签页。脚本不能自行指定代理：请把 `www.dlsite.com` 交给浏览器/系统代理后重试。

> 顺带说明：駿河屋 **没有公开的商品 API**（`api.suruga-ya.jp` 不解析，站内也没有对外的 JSON 搜索接口）。站点搜索框的联想功能由第三方「コトハコ / NaviPlus」（`surugaya-f-s.snva.jp/~surugaya/?action=suggestitem&...`）提供，它不受 Cloudflare 保护、能返回 `itemid / title / url / desc / image / price`，但**只是联想引擎**：长标题（如 `司令・・・笑ってる内にやめような 7`）与多词查询命中数为 0，无法替代搜索，因此脚本仍以搜索列表页 HTML 为准。

### 2.5 非数字分卷与手动指定（v1.2.12 起）

**背景：** 有些作品的「卷」不是数字，而是 `上` / `下`（或 `前編` / `後編`）。此前自动刮削只比较数字卷号，两边都解析不出数字时 Bangumi 侧的映射表是空的，于是每本书都判成「Bangumi 无该卷号」被跳过，而未匹配的行不可勾选、也没有任何人工补救手段。

- **非数字分卷自动识别：** `上` / `中` / `下` / `前編` / `後編` / `上巻` / `下巻` 等写法会归一化成 `上` / `中` / `下`，所以 `作品名 上` 能配上 Bangumi 的 `作品名 (上)` 或 `作品名 前編`（两侧写法不同也能配上）。识别规则刻意保守：只认独立片段或带 `巻` / `編` / `篇` 后缀的写法，`坂道の上`、`上野さんは不器用` 这类标题不会被误当卷标。
- **序号写回：** 非数字分卷也会写进 Komga —— `number` 记 `上` / `下` / `3上`，`numberSort` 取排序值（`上` / `中` / `下` → `1` / `2` / `3`，`3上` 取 `3`）并照常加锁，所以 Komga 列表里既能看到「上 / 下」，排序也不会乱。
- **手动指定：** 确认弹窗里每一行未匹配的书都有「手动指定」按钮，展开后列出**该系列在 Bangumi 下的全部子条目**（含 relation 徽标、日期、id），点一下即可连上；已被其它书占用的条目会置灰并标注「已分配给 …」（一本书只连一个条目，一个条目也只连一本书）。手动指定**只作用于本次刮削**，不会写回 Komga 的 `links` 或任何元数据。
- **按顺序配对（批量兜底）：** 弹窗工具栏的「按顺序配对…」把**未匹配的书**与**尚未占用的 Bangumi 条目**按顺序依次配对，但**先给预览**（列出「文件名 → 待配对条目」）再应用，应用后仍可逐行「换一个 / 取消指定」。默认只处理**已解析出卷号**的书（没解析出卷号的多半是特典 / 画集，硬配只会错位），可用预览里的复选框显式纳入。
- **重复卷号：** 两本书解析出同一卷号（典型：特典文件名里带了正卷编号）时，两行都会标 ⚠ 并写明「与哪一本重复」以及本书卷号来自**文件名解析**还是**位置推断**；**默认仍然勾选**，请核对后自行取消不想要的那一本。汇总行会显示「重复卷号 N 行」。
- **Bangumi 下没有子条目时不再直接报错：** 现在照常打开确认弹窗、把每本书标成未匹配并给出原因（此时候选列表为空，手动指定面板会提示「没有可选的子条目」）。

**已知限制：**

- 粘连且无分隔符的命名（`作品名上`）不识别，避免把 `坂道の上` 这类标题误当卷标 —— 这种请用「手动指定」。
- 缺卷（Komga 比 Bangumi 少）时不要盲目用「按顺序配对」：顺序配对不认内容、只按先后顺序对齐，数量不一致时预览里会给出警告，请逐行核对。
- 系列确实缺某卷、而某个特典文件名恰好解析出该卷号时，会被当成该卷匹配 —— 自动化无法区分，请按 ⚠ 提示人工核对。
- 「手动指定」只在当前弹窗内有效（不持久化）；下次自动刮削仍按卷号键自动匹配。

## 写回的字段与加锁

脚本向 Komga 写入的字段包括：

| 字段（key） | 说明 | 是否加锁 |
| --- | --- | --- |
| `title` | 书名 / 系列名 | 是 |
| `summary` | 简介 | 是 |
| `status` | 连载状态（仅系列；按 Bangumi infobox 的「开始 / 结束」字段判定，Bangumi 没有等价信息时不写入） | 是 |
| `releaseDate` | 发售 / 出版日期（若可解析） | 是 |
| `isbn` | ISBN（若可解析，统一转换为 ISBN-13） | 是 |
| `authors` | 作者 / 作画（以 name + role 列表写入） | 是 |
| `tags` | 标签（与现有 tag 合并去重） | 否 |
| `links` | 来源链接（`bangumi` / `FANZAブックス` / `DLsite` / `FANZA同人` / `駿河屋`） | 否 |
| `readingDirection` | 阅读方向（系列级可选；语言识别为日文时默认从右到左） | 是 |
| `publisher` | 出版社（仅系列级；Bangumi infobox「出版社」/ FANZA·DLsite 的出版社·品牌·サークル等） | 是 |
| `language` | 语言（仅系列级；按系列文件夹名字符属性识别，仅在 Komga 当前为空时写入；书籍页同人本刮削随「同步到系列」写入） | 是 |
| `ageRating` | 年龄分级（**仅系列级**；仅当「同人本搜索」链路（FANZAブックス / DLsite / FANZA同人 / 駿河屋）判定为限制级时写入 `18`，非限制级 / 判不出不写、不加锁） | 是 |
| `number` | 卷号（自动刮削：写回文件名解析出的卷号并加锁，非数字分卷写 `上` / `下` / `3上`；单本刮削：默认填文件名卷号） | 是 |
| `numberSort` | 排序用卷号（非数字分卷取排序值：`上` / `中` / `下` → `1` / `2` / `3`） | 是 |

> 脚本通过在 PATCH 请求中附加 `*Lock=true` 的方式完成锁定；Komga 若已存在该字段的锁定状态则保持不变。
>
> **已锁定字段（v1.2.10 起）**：预览弹窗里锁定字段会带「已锁定」徽标并**默认不勾选**，但可以手动勾选覆盖其值；覆盖时只更新值、不发送任何 Lock 标记，因此该字段在 Komga 中**仍保持锁定**（后续仍不会被内置扫描覆盖）。自动刮削不受影响，仍按 `currentMetadata={}` 强制覆盖所有可写字段。

> **书籍页同步系列字段（v1.2.11 起）**：在书籍页用「同人本搜索」（FANZAブックス / DLsite / FANZA同人 / 駿河屋）刮削时，除书籍自身字段外，预览弹窗还会单独列出以下**系列级**字段并默认勾选（可逐项取消）：系列标题、系列排序标题（本次抓到的作品标题）、系列简介、系列出版社（抓取源信息表里的 出版社 / ブランド / メーカー / レーベル / サークル）、系列阅读方向（默认「从右到左」；系列文件夹名识别为日文时同样预选「从右到左」）、系列语言（按系列文件夹名识别，仅当 Komga 系列 `language` 为空且未锁定时出现）、限制级时的系列分级 `18`；抓取数据带别名时还有系列别名（当前四个源暂不提供别名）。写入时先 PATCH 书籍元数据，再 PATCH 所属系列 `/api/v1/series/{id}/metadata` 并附加 `*Lock=true`（该系列对应字段当前已锁则只更新值、不加锁）。Bangumi 源、系列页以及没有 `seriesId` 的书籍页不涉及该同步，自动刮削也不受影响。

## 兼容性与依赖

- **浏览器：** 现代浏览器（Chrome / Edge / Firefox / Safari 最新一两个版本）。
- **Userscript 管理器：** 必须支持 `GM_xmlhttpRequest` / `GM_setValue` / `GM_getValue` / `GM_registerMenuCommand`。
- **Komga 版本：** 任何暴露 `/api/v1/series/{id}`、`/api/v1/books/{id}`、以及对应 `PATCH /metadata` 接口的版本。
- **Bangumi API：** 使用官方 `https://api.bgm.tv/v0/...`，无需鉴权（公开数据）；脚本在请求头中使用 `User-Agent: KomgaMetadataScraper/{版本号}` 标注自身。

## 注意事项

- 脚本不会上传任何数据到第三方；所有请求均在浏览器（通过 GM_xmlhttpRequest）发出，并直接作用于你自己的 Komga 实例。
- 刮削结果**仅供你个人整理馆藏使用**，请遵守相关网站的 robots 与使用条款。
- 自动刮削的默认节流为 **2 秒 / 请求**，可以在设置面板中调节 `rateLimit.minInterval`；若需要更激进的抓取，请自行承担被远端限流的风险。
- **FANZA ブックス / FANZA 同人、DLsite（搜索页）与駿河屋的页面可能会随时变更 DOM 结构**，一旦解析失败请在本仓库提出 Issue；这些都只支持页面上的手动“刮削”，不提供自动刮削。（DLsite 详情自 v1.2.13 起改走站点自用的 JSON 接口，不再依赖详情页 DOM。）
- 駿河屋 全站都有 Cloudflare 人机校验（商品详情页必拦，搜索列表页在本机 IP 被判可疑时也会拦）。搜索用列表页数据，**v1.2.15 起选中结果后会自动补抓商品详情页**（补全作者与简介；详情页同样靠「桥接标签页」重取，失败静默退回列表页数据）。若直连与桥接都失败，可只让 `suruga-ya.jp` 走代理换出口 IP 后重试。DLsite 已不再使用桥接标签页：直连失败时请让 `www.dlsite.com` 走代理后重试（脚本不内置代理）。

- **新增駿河屋兜底源（只兜底、不混排）**：Fanza / DMM 没搜到（0 条结果或请求失败）时才会改搜駿河屋，两者**绝不并行、结果也绝不混在一起**；兜底命中时弹窗提示「FANZA/DMM 未找到结果，已自动改用「駿河屋」兜底」（若 FANZA 是请求失败则附上原因）。
  - 每条搜索结果卡片都新增**来源角标**（`FANZA/DMM` 或 `駿河屋`），预览与写回也按结果自身的来源处理。
  - 駿河屋只取搜索列表页（详情页有 Cloudflare 校验），可解析出作品名 / 作者 / サークル / 発売日 / 封面 / 商品链接；駿河屋只有中古在售信息，**不猜测连载状态**，因此不写 `status`。
- **修正 Fanza 详情页解析**：`ジャンル` 标签改为逐个链接取值（此前把整段文本按分隔符切分，十几个标签会粘成一条巨型字符串），并过滤掉「男性向け / 成人向け / 新作」这类受众与营销标记；信息表里没有出版社字段时回退取圈名（`a.circleName__txt`）。
- 触发兜底且两源都没有结果时，弹窗会明确提示「FANZA/DMM 与 駿河屋 均未找到结果」，而不是误报成「无法访问」。
- **新增「限制级」判定并写入系列分级（`ageRating`）**：FANZA/DMM 详情页信息表 `ジャンル` 含 `成人向け`、或駿河屋列表条目带 r18 角标（`img[src*="r18"]` / `p.condition` 命中 `18禁`·`アダルト`）时判定为限制级，写入**系列级** `ageRating = 18`（Komga 只有系列元数据有该字段，ComicRack 枚举里 `Adults Only 18+` / `R18+` / `X18+` 都映射为 18）。`全年齢向け` 与「判不出」一律不写该字段、也不加锁，与现有「判不出就不猜」策略一致。
  - 同时把 `全年齢向け` 补进 FANZA 标签黑名单（此前会漏进 `tags`）；`成人向け` 也不再写进标签，改由 `ageRating` 承载。
- **书籍页刮削同步所属系列标题**：在书籍页用 FANZA/DMM（含駿河屋兜底）刮削时，预览弹窗会额外列出**系列级**字段「系列标题（同步到系列）」「系列排序标题（同步到系列）」（取本次抓到的作品标题，默认勾选、可逐项取消），限制级时还有「系列分级 (18禁，同步到系列)」。锁定状态按父系列当前元数据判定（未锁才加锁、已锁则只更新值）。确认后先 PATCH 书籍元数据，再 PATCH 所属系列 `/api/v1/series/{id}/metadata`；Bangumi 源、系列页与没有 `seriesId` 的书籍页行为不变，自动刮削也不受影响（不会额外发系列请求）。
- **修复駿河屋兜底被 Cloudflare 反复拦下的问题（HTTP 403 / `Just a moment...`）**：此前脚本对外部请求使用 `anonymous: true`（不带浏览器 Cookie）且写死了 Chrome/120 的 `User-Agent`，所以即使你在浏览器里通过了 Cloudflare 人机校验，脚本请求也**拿不到**那张 `cf_clearance`（而且 `cf_clearance` 与 UA 绑定，写死的 UA 也会让它失效），于是每次都以「请在浏览器里打开一次站点」告终却始终无效。
  - 现在駿河屋 的请求会先通过 `GM_cookie` 读取浏览器里 `suruga-ya.jp` 域的 Cookie，连同必需的 `safe_search_option=3` 一起显式带上，并**沿用浏览器真实 UA**（不再写死），从而复用你已通过的校验；Cookie 读取失败时自动退回旧行为，不影响其它环境。
  - 因为需要 `GM_cookie`，脚本新增了该权限；更新后请允许新权限（详见 [安装](#安装) 说明）。
  - 报错文案也同步改写：明确提示要在**同一个浏览器**里通过校验、并说明代理 / VPN 改变出口 IP 会导致校验 Cookie 失效。
